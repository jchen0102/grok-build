QA 和产品锁本身已经闭环。还没被认真对待的，主要是**评分人怎么交、怎么点**，不是再补 20 条用例。

**1. compose 是按这台坏网卡的 VM 写的，不是按评分人笔记本写的。**  
API / nginx 都走 `host.docker.internal`，Postgres 还把 **5432 打到宿主机**。本机没容器互通时这是对的；评分人 `docker compose up --build` 时，5432 被占用、Linux 过旧没有 `host-gateway`、或者他们以为该用 `db`/`api` 服务名，都会直接起不来。考试完成标准是「compose 一键」，这比再测一条 CSV 边界更致命。

**2. `ai-log/` 几乎是空的。**  
考试要交对话记录，仓库里只有一篇竖切摘要。README 指针在，原文不在。评分人如果按「必须用 AI 并提交记录」打分，这里比测试覆盖更空。

**3. 时间窗控件会偷偷砍秒。**  
默认窗是 `…00:00:05Z`～`…23:59:35Z`，`datetime-local` 只精确到分钟。评分人只要点一下日期框，结束时间会变成 `23:59:00Z`，闭区间少 35 秒。顶栏还标着 UTC，Chrome 却可能显示成 `03/01/2026, 12:00 AM`。口径锁的是 UTC，控件并没有真正保住秒和时区。

**4. 「导入」会丢掉当前窗。**  
`看板/聚合/原始记录` 带着 `search` 跳，`导入` 是裸 `/import`。这是产品锁，但评分人从聚合点导入再回来，会看到窗被 reset 成 min–max。不修也可以，README 里最好有一句，免得被当成 bug。

**5. 提交物长相比功能更容易被减分。**  
仓库是整棵 Rust `grok-build` 再塞进考试 App；PR 还是 draft。评分人 clone 到的是一个巨大无关树 + 一个中文质量台。若题目要独立交卷，这比 p95 测漏更扎眼。

**6. 导入还有几条评分人随手就能踩、计划没写的。**  
Excel UTF-8 BOM 会让表头对不上；`io.LimitReader(20MB)` 超限是截断不是明确报错；`GET` 和 `get` 会变成两个聚合键（只 trim、不规范化）。这些都不值得为了考试去开产品轮，但 BOM 和 compose 值得在 README 用一句话挡一下。

**不必再开的：** 登录、异步导入、4xx 当错误、httptest、把 Playwright 推进 PR。那是锁，不是遗漏。

若还要动，只动两件和评分路径有关的：让 compose 在普通 Docker 上也能起（服务名互通，5432 不必对外），以及把真正的对话记录补进 `ai-log/`。时间窗砍秒只有评分人会去拧控件时才值得修。
